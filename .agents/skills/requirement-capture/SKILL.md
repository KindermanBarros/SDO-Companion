# Skill — Requirement Capture

Note: [feature-specification](../feature-specification/SKILL.md) supersedes this skill for full feature specs. Use this lightweight capture only when a workflow explicitly requests `docs/current/requirement-summary.md` via [requirement-summary-template.md](../../../harness/templates/requirement-summary-template.md).

## Workflow
1. Read the user's request and affected capability files in `docs/product/requirements/`.
2. Draft `docs/current/requirement-summary.md` covering Requirement Summary, User Goal, Expected Behavior (testable outcomes), Business Rules, Known Constraints, Non-Goals, the 10-row [Rule Applicability](../../../harness/templates/rule-applicability-template.md) table, Explicit Assumptions, and Open Questions.
3. Save any user-supplied mockups to `docs/current/design/`.
4. Resolve all open product questions with the user before advancing to planning or implementation.
