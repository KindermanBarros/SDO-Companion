Implementation: CharacterSyncPatch uses stable IDs and URL-safe encoded element keys for inventory/itemStates, canonical and legacy conditions, abilities/powers/mysticAbilities, personal notes, attributes and nested skills. Untouched lists retain their order; concurrent edits to different properties are rebased. Tombstones prevent stale edits from resurrecting deleted elements. Editor baselines capture actual intent; acknowledgements discard only the edits included in that upload and retain later changes. Duplicate element IDs are rejected when the affected list changes rather than silently collapsed.
All collaboration metadata stays in fieldUpdatedAt: @pending/path is local intent, @server/path is a committed logical revision, @deleted/path is a tombstone, @revision is the sheet sequence, @protocol marks the upgraded writer, and @operation/key is a durable action receipt. Firestore transactions advance the sequence; updatedAt advances monotonically with overflow checks, but remains a display timestamp rather than authoritative UTC. Client clock skew cannot select the winner of upgraded writes.
Session commands now read the latest remote sheet, apply arithmetic deltas and consumption in a transaction, and write the sheet plus campaign audit together. Repeating the same operation key cannot spend twice. Campaign activity is checked in the transaction. Remote replies preserve newer local edits and pending deletions. Old unmarked local edits against an upgraded sheet enter the existing explicit review flow instead of being silently overwritten.
Release dependency: publish the accompanying firebase/firestore.rules before releasing this client. The rules permit checking a missing UUID for transactional creation, require the next revision on upgraded writes, and reject old clients overwriting an upgraded sheet; narrowly scoped campaign unlink operations remain compatible.
